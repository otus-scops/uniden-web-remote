# BCT15X メモリエディタ機能 実装計画 (FreeSCAN代替)

## 概要
BCT15Xの実機プロトコル（DMAリンクリスト構造: `SIH`, `SIN`, `GIH`, `GIN`, `CIH`, `CIN`等）を実装し、スキャナーから全システム・グループ・チャンネルを正確に読み書きできるようにします。
また、Web UI上でFreeSCANのように直感的かつ一括でチャンネル編集（周波数、モジュレーション、トーン等のスプレッドシート風グリッド編集、CSV/JSONインポート・エクスポート）が行える本格的なエディタ画面を構築します。

## ユーザー確認事項 (User Review Required)

> [!IMPORTANT]
> **1. 実機メモリ書き込み（アップロード）時の安全性**
> 実機への一括書き込みは、既存のメモリを上書き・再構築する処理を伴います。安全のため、**「スキャナーへ書き込み」を行う前には自動でローカルJSONバックアップを保存する設計**とします。
> 
> **2. ローカルLLMの利用について**
> 設定ルールに基づき、本機能の実装やテストデータ生成等でローカルLLM（llama-local / Ollama等）を利用するか、利用される場合のモデル名についてご希望があればお知らせください。

## 現状の課題とアーキテクチャ分析

1. **実機読み出しの未実装（ダミーデータ返却）**
   - 現在の `src/scanner/programmingController.js` は固定の配列データを返しているため、実機の全データが取得できていません。
   - BCT15Xは **DMA (Dynamic Memory Architecture)** を採用しており、ポインタ（Next Index）を辿るリンクリスト形式でメモリが保持されています。
   - `SIH` (System Head) → `SIN` (System Info) → `GIH` (Group Head) → `GIN` (Group Info) → `CIH` (Channel Head) → `CIN` (Channel Info) の順にチェーンを走査する必要があります。

2. **エディタUIの操作性**
   - 現在の `memoryEditor.js` は1チャンネルずつフォーム入力する単一ノード編集のみです。
   - FreeSCANのように、数十〜数百の周波数を一覧・一括編集するには**テーブル／グリッド型（スプレッドシート風）のチャンネルエディタ**が必要です。

```

│  Phase 1: BCT15X DMA プロトコル通信の実装 (バックエンド)        │

│  - CSY/DSY, CGR/DGR, CCH/DCH コマンドによる作成・更新・削除  │
│  - プログラミングモード中の進捗通知 (WebSocket / SSE)        │
└──────────────────────────────┬──────────────────────────────┘
                               │

│  Phase 2: 本格スプレッドシート型エディタUIの構築 (フロント)    │

│  - 中央: FreeSCANライクなチャンネル一覧グリッド (インライン編集) │
```

## 検証手順 (Verification Plan)

### 1. プロトコル単体検証
- モックモードおよび実機接続にて、`SIH` から始まるリンクリストの走査が終端（-1）まで正しく動作するか確認
- 取得されたJSONデータに、実際の周波数・チャンネル名・変調・トーンが含まれているか検証

### 2. UI操作・編集検証
- グリッド上でチャンネル名、周波数、変調、トーンを直接編集し、保存されるか
- 新規行の追加、削除、複数行のコピー＆ペーストが動作するか
- CSV/JSONのエクスポートおよびインポートが正しく行えるか

### 3. 実機ダウンロード＆アップロード検証
- BCT15X実機から全データをダウンロードし、進捗バーが100%まで進むか
- 編集したデータを実機にアップロード後、スキャナー本体のディスプレイで周波数やチャンネル名が更新されているか
